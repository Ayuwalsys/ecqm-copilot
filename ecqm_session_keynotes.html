1 · Project identity
What it is
Clinical Quality Measure Copilot (eCQM/HEDIS)
A FHIR-native, privacy-preserving AI service that automates clinical quality measure abstraction with clinician-verifiable evidence, full provenance, and multi-site reproducibility.
What it solves
The 5 core outcomes
① Clinician time drain (50–70% reduction) · ② Reporting delays → near real-time · ③ Site inconsistency → standards-based · ④ Black-box AI → evidence spans · ⑤ Patient care gaps closed faster
NIW framing
Independent open research — no employer tie
Anchored in public datasets (MIMIC-IV-Note, Synthea, n2c2, CMS public eCQM specs). Published under personal research identity. Open spec benefits national infrastructure regardless of employer.
2 · Architecture keynotes
Pipeline layersIngest + PHI guard → Section-aware retrieval → RAG + LLM extraction → Deterministic eCQM rules → Safety validation → Reviewer UI → MeasureReport + Provenance (FHIR)
Hybrid engineLLM handles unstructured note reading; deterministic YAML rules enforce time windows, value thresholds, and exclusions. Conflict between the two → auto-route to reviewer. Neither alone is trustworthy enough.
Evidence spansEvery extracted fact carries character-level offsets back to the source document. Field with value but no span = hallucination flag. Schema-first, not a post-processing check.
Versioned logic libraryMeasure logic in measures/*.yaml with cryptographic hashes. Every decision object references the exact logic version — reproducible audit years later.
Provenance ledgerWho/what/when/why per decision. Emits FHIR MeasureReport + Provenance on reviewer commit. site_id + tenant_id in every seed from day 1.
DeploymentFastAPI backend (Render.com) + Streamlit frontend (Streamlit Community Cloud or Render). Mock mode runs offline — demo works without backend. render.yaml auto-configures both services.
3 · Measures — phase decisions
Phase 1 — start here
diabetes_hba1c · ami_8a
Two measures with different abstraction profiles: HbA1c = lab value + threshold (semi-structured); AMI-8a = time-stamped procedural (highly structured). Contrast early, validate the pipeline, then expand.
Phase 2 additions
STK-4 · VTE prophylaxis · Heart Failure education
Add after Phase 1 pipeline is validated. STK-4 and VTE add complexity (multi-condition logic). Heart Failure education adds documentation-based abstraction.
Phase 3 (6–12 months)
HEDIS multi-period lookback
Hypertension control, colorectal cancer screening — require multi-period lookback logic. Target 8–10 total measures live by 12-month milestone.
4 · Data source suitability rulings
Source
Suitability
Key constraint

✅ Use now
Fully open federal regulation. Zero licensing restrictions. Strongest NIW anchor.
MTSamples
✅ Use now
4,999 free de-identified transcription samples. Fills outpatient note gap MIMIC leaves. No DUA. Download as CSV.
5 · Annotation protocol keynotes
ToolLabel Studio with 6 labels: HBA1C_VALUE · HBA1C_ABSENT · DIABETES_DX · QUALIFYING_VISIT · DENOMINATOR_EXCLUSION · DATE (nested)
IRR gateCohen's Kappa ≥ 0.80 per label class before any model training. 30-case overlap batch per annotator pair. Calibration session if κ < 0.70.
Scale100–150 cases/measure. 80/20 train/test split. Test set locked — never used for prompt tuning.
Minimum span ruleShortest contiguous span that uniquely identifies the fact. Trim whitespace, conjunctions, punctuation from boundaries.
Annotation guideFull guide produced (diabetes_hba1c_annotation_guide.docx) — 10 sections including decision tables, worked examples, Label Studio XML config, IRR process, and escalation rules.

Day 60LLM extraction F1 ≥ 0.85 on held-out set · Hallucination guard blocking ≥ 95% of span-less claims · LLM F1 must exceed rules-only F1 · Reviewer UI usable by non-engineer
